# Changelog 3.0.0

Support of TYPO3 14. The TYPO3 13 compatible code stays on the 2.x line.

## New Features
- The string detail screen can show the translations of other languages as a reference under each
  field, so a translator sees how a string was solved elsewhere without leaving the screen.
- The fields of that screen can be switched to text areas, for labels that need a line break.
- The database export can prefill the target of the exported file from an already existing
  translation instead of repeating the source.
- Right to left support. Translation fields and translation tables carry the direction of the
  language they hold, so Arabic or Hebrew is edited right to left even in a left to right backend,
  and the stylesheet uses logical properties so an RTL backend mirrors correctly.
- All backend screens were reworked on the TYPO3 backend design language and now follow the
  backend colour scheme including dark mode.

## Breaking
- Requires TYPO3 14.0 - 14.99 and PHP 8.2+. Use 2.x for TYPO3 13.
- `ext_tables.php` has been removed, it is deprecated since TYPO3 14.3. The registration of the
  XLF overrides moved to `ext_localconf.php`.

## Security
- The export and import checked module access only. They now verify that the user may read the
  tables being exported, and that the user may modify the table and edit the page of every record
  being imported. The import writes with the query builder rather than the DataHandler, so none of
  this was enforced before and any user reaching the module could write every translatable table
  on every page.

## Adjustments to removed TYPO3 14 API
- `LanguageService::includeLLFile()` was removed. Labels are read through
  `LanguageService::getLabelsFromResource()` instead. That method returns a flat map for one
  language, so source and target are read in two passes and reassembled into the structure the
  detail view and the exports already used. The change is confined to
  `TranslatorController::loadLabels()`, the templates are untouched.
- `CharsetConverter::specCharsToASCII()` was removed, `utf8_char_mapping()` is used instead.
- The `Icon::SIZE_*` constants were removed, the `IconSize` enum is used instead.
- The TCA `interface` section was removed from `tx_hdtranslator_ai_languages`.
- Extbase no longer supports annotations, the `@IgnoreValidation` annotation of the save action
  was removed. The argument has no validators, so nothing had to replace it.
- `ds_pointerField` and the multi entry `ds` array were removed. The FlexForm data structure of a
  record is now resolved through `FlexFormTools::getDataStructureIdentifier()` and
  `parseDataStructureByIdentifier()`, which also picks up record type specific structures from
  `columnsOverrides` and resolves `FILE:` references. The previous implementation parsed the raw
  `ds` value and silently did nothing for both cases.
- `FlashMessage::ERROR` is replaced by `ContextualFeedbackSeverity::ERROR`.

## Adjustments to deprecated TYPO3 14 API
- `FlexFormService` is deprecated and removed in TYPO3 15. `FlexFormTools`, into which it was
  merged, is injected instead.

## Fixes
- Exports contained a large amount of empty entries. Fields of a type that carries no translatable
  text registered an export key without ever receiving a value, and every one of those became an
  empty trans-unit. A page export shrank from 60 entries with 33 empty ones to 21 real fields.
  Types without translatable text are no longer offered by default, naming them in
  "translator_export" still exports them.
- `SiteNotFoundException` moved in TYPO3 14, so the catch that falls back when a page has no site
  configuration never matched and the module raised the exception instead.
- Duplicating inline records on import read its record type overrides from an undefined variable,
  so type specific "foreign_table", "foreign_field" and "MM" settings were silently ignored.
- The per import bookkeeping of `DatabaseEntriesService` was static, so two runs in one request
  added up into each other. It is instance state now and the service is no longer shared.

## Housekeeping
- Removed the registration of the `getButtonsHook`. That hook was removed in TYPO3 12 and the
  method it pointed at did not exist, so it had been dead the whole time. The docheader button is
  added through the `ModifyButtonBarEvent` listener.
- Removed unused imports, including the never used `FlexFormService` injection of the controller.

## Known remaining deprecations
- The `make*()` methods of `ButtonBar`, `Menu` and `MenuRegistry` are deprecated in TYPO3 14 in
  favour of the reworked Buttons API with Components. They still work and were not migrated yet.
- `ext_emconf.php` is deprecated since TYPO3 14.2.
