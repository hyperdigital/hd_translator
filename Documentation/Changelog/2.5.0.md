# Changelog 2.5.0

## New Features
- A screen that answers which languages people actually ask for: unique visitors per language for
  today, seven days, thirty days and in total, whether that is more or less than the thirty days
  before, how much of the language is already translated, and whether it exists as a real language
  of a site. Every column sorts, in the browser, because the list is at most a hundred or so rows.
  That is the question the counting was added for: which language is worth building as actual
  pages.

- The same screen draws the demand over time. A table of totals hides a language that is
  climbing behind one that was popular last month and is now flat, so a chart shows the unique
  visitors per day over the last 7, 30, 90 or 365 days. A crosshair snaps to the nearest day and
  names every language at once, sorted by value, so two series that cross stay readable; clicking
  a legend key hides that language and the axis refits. Colour follows the language rather than
  its rank, so narrowing the range or hiding a series never repaints the ones that stay. It is an
  SVG the screen draws itself - no library and no second request - and the palette is validated
  for colour vision deficiency, with its own steps for dark mode.

- Editing a screen full of labels and leaving it no longer loses the work without a word: the
  browser asks before leaving, the save button carries a mark while something is unsaved, and
  ctrl or cmd and S saves without reaching for the docheader.
- A form that was submitted says so, and tables marked sortable sort by any column in the browser.

## Changes
- The request and string counters are gone from the statistics, nobody needed them. A row is now
  its own primary key, which is 137 bytes against the 359 a row with counters and a secondary
  index took. At five thousand visitors a day that is 238 MB a year rather than 625.
- Old rows are dropped once a day rather than only when somebody opens a screen - on an
  installation where nobody did, the table grew without end.
- The demand screen is no longer a separate entry in the module menu, where it read as an
  unrelated area. It belongs to the AI translations and is reached from their list, like the
  other screens of that area already were. The menu keeps one entry for the whole area, and the
  demand screen carries its own way back, because the menu entry is already the selected one and
  picking it again navigates nowhere.

## Fixes
- The trend column said a bare percent sign instead of "new" for a language nobody had asked for
  in the month before. It asked `{row.trend} === NULL`, and Fluid has no identity operator, so the
  condition never held. Whether a trend exists is now decided in PHP.

## Upgrade
- Run the database analyzer. `tx_hdtranslator_ai_request` is rebuilt; it only holds counting data
  of the last year, nothing that cannot be collected again.
