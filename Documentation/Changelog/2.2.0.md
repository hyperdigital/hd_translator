# Changelog 2.2.0

## New Features
- Multi-site support: the module now resolves the site configuration from the page or record
  being exported, so source and target language selects show the languages of the correct site.
  Previously the `id` parameter was expected but never delivered (the module has no page tree),
  which merged the languages of all sites into one list and broke installations whose sites use
  different default languages.
- The docheader button, the context menu entry and the list module action now pass the page along,
  so exporting a record from the List module keeps its site context.
- The translation search in the Translator module is available again.

## New Features
- The database export can optionally prefill the `<target>` of the exported XLF from an already
  existing translation, so translators can correct what is there instead of starting from scratch.
  The option is off by default, because content to be translated is usually new. Fields without an
  existing translation keep repeating the source value as before. Available for the page content
  export, the table export and the single record export.

## Fixes
- Exporting a language other than the default one now also exports the inline children and file
  references of that language. Only the scalar and FlexForm values followed the selected source
  language before, while inline records and `sys_file_reference` rows were always read from the
  default language, so a translated record could be exported with a mix of both languages. Export
  keys keep using the default language uid, so the round trip through the import is unchanged.
  When a translated record has no own children, the default language ones are exported as before.
- Fields of the TCA type `file` no longer fall through into the inline handling. The fall through
  passed the field name of the last processed child instead of the file field itself.
- The DeepL frontend endpoints (`_hdtranslator_translate`, `_hdtranslator_fetchSupportedLanguages`)
  validate their input: only synchronized target languages are accepted, and the amount and length
  of submitted strings is capped. They return proper JSON responses and status codes instead of
  writing directly to the output.
- DeepL API failures no longer terminate the request with a raw `exit`; they raise an exception and
  are reported back as an error response.
- A short or failed DeepL response can no longer shift the mapping between source strings and their
  translations.
- `allLocallangs`: the generated `locallangConf.php` is now loaded when a storage path *is*
  configured. The condition was inverted.
- The storage path check evaluated an always empty substring, so the leading slash handling
  never worked as intended.
- The file list of a category built a different filename than the detail, save and remove actions,
  so opening a translation from a page context could target the wrong file.
- Backend downloads (XLF, XLS, CSV, JSON and the ZIP exports) are returned as regular responses
  instead of `echo` plus `die()`.
- All writing database queries use `executeStatement()` instead of `executeQuery()`.
- Empty ZIP archives no longer produce a broken download; the plain XLF is returned instead.

## Housekeeping
- Removed ~500 lines of unreachable code from `TranslatorController`, including a second, older
  import implementation still using the removed `execute()`/`fetch()` Doctrine API and a call to
  the long gone Extbase `objectManager`.
- Removed stray imports of classes from packages that are not dependencies.
- The PHP requirement is declared as 8.2 in both `composer.json` and `ext_emconf.php`; the code
  already used PHP 8.1+ syntax and TYPO3 13 requires 8.2.
- Added a documentation entry point so the manual renders on docs.typo3.org.
