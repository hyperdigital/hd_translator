# Changelog 3.2.0

## New Features
- The demand screen draws the demand over time. A table of totals hides a language that is
  climbing behind one that was popular last month and is now flat, so a chart shows the unique
  visitors per day over the last 7, 30, 90 or 365 days. A crosshair snaps to the nearest day and
  names every language at once, sorted by value, so two series that cross stay readable; clicking
  a legend key hides that language and the axis refits. Colour follows the language rather than
  its rank, so narrowing the range or hiding a series never repaints the ones that stay.

  It is an SVG the screen draws itself - no library and no second request - built from one query
  that groups the rows already counted by language and day. Days nobody asked come back as zero,
  so every series has the same length. The palette is validated for colour vision deficiency and
  carries its own steps for dark mode, and the table below the chart is the same data for anyone
  the chart does not serve.

## Changes
- The demand screen is no longer a separate entry in the module menu, where it read as an
  unrelated area. It belongs to the AI translations and is reached from their list, like the
  other screens of that area already were - a language, the original sources, the translations of
  one original. The menu keeps one entry for the whole area and stays active while demand is
  open, and the list gained a button beside the two it had. The button is in the empty state too:
  before anything is synchronised is exactly when the question *what should I synchronise* gets
  asked. Because the menu entry is then already the selected one, picking it again navigates
  nowhere, so the demand screen carries its own way back.

## Fixes
- The trend column said a bare percent sign instead of "new" for a language nobody had asked for
  in the month before. It asked `{row.trend} === NULL`, and Fluid has no identity operator, so
  the condition never held and the cell it sorted by stayed empty. Whether a trend exists is a
  question PHP can answer, so the controller answers it and the template reads the flag.

## Documentation
- The three settings that had no entry at all are written down: whether the counting runs
  (`aiRequestStatistics`), how long its rows are kept (`aiRequestStatisticsRetention`) and how
  many requests a minute the endpoint accepts (`requestsPerMinute`).
- The documented endpoint limit was stale. It said fifty strings per request; it has accepted
  five hundred since the service started splitting what it forwards by request size rather than
  by a count. The rate limit and its HTTP 429 were missing as well.

## Upgrade
- Nothing to run. The chart reads the rows `tx_hdtranslator_ai_request` already holds.
