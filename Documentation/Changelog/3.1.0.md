# Changelog 3.1.0

## New Features
- The AI translation overview counts how many people asked for each language, not only how many
  strings it holds. The number of translated strings says how much text a language has; it does
  not say whether anybody wanted it. DeepL counts requests, and analytics cannot tell a visitor
  who used the translation from one who did not. The overview now shows unique visitors per
  language for today, 7 days, 30 days and in total, next to the number of requests, which is what
  decides whether a language is worth maintaining as real pages.

  Counting is on by default and needs no change in a project that already uses the frontend
  translation; it happens in the endpoint the frontend calls.

- The frontend keeps what it already had translated in the browser, per language, so opening a
  second page swaps most of it without asking the server at all, and asks only for strings it has
  not seen. It also translates what is in the viewport first, and picks up content rendered later
  - tabs, modals, anything loaded after the page - through a MutationObserver, which previously
  stayed in the source language. The entries expire after a day, because an editor can correct a
  translation in the backend and nobody would otherwise see the correction.

  Based on the module the elatec project wrote for itself, adapted to stay a plain global script
  so no build step is needed.

## Privacy
- What is stored is one row per language, per day, per visitor, where the visitor is an HMAC of
  the address and the user agent keyed with the installation's encryption key **and the day**. The
  same person therefore hashes differently tomorrow, and yesterday's rows can no longer be tied to
  anybody. No address and no user agent is written anywhere.
- Rows are dropped after a year, configurable, and the overview prunes them when it is opened.
- The whole counter can be switched off in the extension configuration.

## Upgrade
- Run the database analyzer, this adds the table `tx_hdtranslator_ai_request`.

## Fixes
- Two editors exporting at the same time no longer overwrite each other's archive. Both exports
  wrote the same `translation.zip` into one shared directory, which the import used as well, and
  whoever finished first deleted the whole directory afterwards - taking the other one's files
  with it. Every run gets a directory of its own now and removes only that one, including when the
  archive stays empty.
- Calls that could be handed `false` where a string is required are guarded: a label that is not
  valid UTF-8 no longer turns the JSON download into a fatal, a record that was deleted meanwhile
  comes back as an empty array instead of `false` that every caller then indexed into, and a
  request body that is not the JSON the detail screen posts is recognised instead of warning and
  silently saving nothing.

- The screens listing the AI translations of a language and the distinct source texts are paged
  and can be searched. They used to render every row of the table into one page, which on a site
  that has been translating for a while is tens of thousands of them.
- The list of distinct source texts was not distinct at all. It asked for `SELECT DISTINCT *`,
  and with the uid in the row every row is distinct by definition, so the same source appeared
  once per language. It now groups by the source and says how many languages each one has.
- The database export serves a single record as the file it is instead of an archive with one
  entry in it, and an export that found nothing says so instead of offering a file that contains
  the explanation.
- The coverage screen asks one query per table rather than two per table and language, which was
  a few hundred queries for one screen on a site with several languages.
- The translation endpoint refuses a visitor who sends more requests than the configured limit
  per minute, with 429 and a `Retry-After`. It has no login, because the frontend has to reach
  it, and every string it has not seen is paid for at DeepL, so the number of requests was the
  one thing nothing bounded.

## Housekeeping
- `curl_close()` is gone. It has had no effect since PHP 8.0 and is deprecated in PHP 8.5, where
  every DeepL call wrote a deprecation into the log.
