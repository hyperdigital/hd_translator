# Changelog 2.2.1

Fixes backported from the 3.x line, all of them present in 2.2.0.

## Fixes
- Every export touching a file reference died with
  `Class "Hyperdigital\HdTranslator\Services\Connection" not found`. The helper reading the file
  references of a record used `Connection::PARAM_INT` without importing the class, so PHP resolved
  it inside the extension namespace. Introduced together with the source language export in 2.2.0.
- `duplicateInlineData()` read its record type overrides from an undefined variable instead of the
  parent row it is given, so type specific `foreign_table`, `foreign_field`, `foreign_table_field`,
  `foreign_match_fields` and `MM` settings were silently ignored while duplicating inline children
  on import.
- `ext_conf_template.txt` ended without a trailing newline, so TYPO3 dropped its last setting and
  `deeplApiKey` never appeared in the extension configuration form. The key could therefore not be
  entered through the backend at all, which kept the whole "AI Translations" tab hidden.
- EXT:extensionmanager is optional in composer based installations. `ListUtility` was a constructor
  dependency of the controller although only the optional "synchronize all locallang files" feature
  uses it, so on an installation without that extension the dependency injection of the whole module
  failed and no screen could be opened. It is resolved lazily now, the synchronize button is hidden
  when the extension manager is missing, and composer.json suggests it.
- Replaced a leftover `<f:debug>` in the categorized detail view, which dumped the whole variable
  container onto the page, with the item rendering that branch was meant to do.

## Housekeeping
- Added a .gitignore, so a `composer install` inside the extension does not leave untracked build
  artefacts behind.
