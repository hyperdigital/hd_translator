# Changelog 3.6.0

## New Features
- **Where the asking comes from.** A language the site already has reads as demand and may be
  anything but: somebody on the english page who asks for german wants a german page, while a
  banner offering german on a page that is already german is a defect inflating the same number.
  The counting rows know what was asked for and never where from, so the two were one figure.

  The language version a request came from is now resolved from the referer that is already
  being read, by matching it against the bases of the site configuration. The demand screen
  lists it per language and calls out two cases:

  - **The page was already in this language** - a defect report about the banner, not demand. It
    gets a tile of its own in a warning colour so nobody reads it as interest in a language.
  - **It was asked for although it exists as real pages** - those visitors could have been sent
    to the page instead of to a translation. That is a question about navigation or a missing
    redirect.

## Privacy
- Only the resolved language is stored, never the url: one row per language pair per day with no
  visitor column at all. It counts requests, not people, and is bounded by construction - a day
  holds at most as many rows as there are language pairs, whatever the traffic.

## Changes
- The host of the referer is matched against the site configuration first and dropped on a second
  pass. A staging or ddev copy answers on a host the configuration does not name - its
  baseVariants are resolved per request and are not visible from an eID - and without the second
  pass such an installation would attribute nothing at all.
- The longest matching base wins, so `/de-de/` beats the root language of the same site.
- An insight tile no longer stretches the row it sits in when its label is long.

## Upgrade
- Run the database analyzer. One table is added, `tx_hdtranslator_ai_request_source`; it starts
  empty and fills as requests come in. Nothing else changes.
