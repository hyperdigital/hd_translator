# Changelog 3.0.2

## Fixes
- DeepL authentication. DeepL removed the legacy `auth_key` parameter in November 2025 and
  answers requests carrying it with 403, so every translation that was not already cached failed
  and the frontend kept showing the untranslated text. The key is sent as
  `Authorization: DeepL-Auth-Key` now. A body still built the old way has the parameter stripped
  rather than sent, so callers outside the extension keep working.
- The error of a failed DeepL call now carries DeepL's own response body. Without it a 403 for a
  retired authentication method and a 403 for an exhausted quota looked exactly alike.

## Performance
- The cached strings of a request are resolved with one query instead of one per string, and the
  fresh ones are written in one statement instead of one per string. A frontend batch of fifty
  strings meant a hundred queries.
- Index on `tx_hdtranslator_ai_translation (target_language, original_source)`, which those
  lookups never had. Run the database analyzer after updating.
- The translate endpoint accepts 500 strings instead of 50 and splits what it has to forward to
  DeepL itself, by the size of the request rather than by a count, which is what DeepL actually
  limits. 50 was taken for a DeepL limit and passed straight through, so a page was translated in
  one request per fifty strings, each one a round trip and a TYPO3 bootstrap. What a single
  request may cost is unchanged, it is still bound by the character limit.
- The frontend asks for every distinct string once instead of once per occurrence, runs its
  batches a few at a time instead of strictly one after another, and leaves out strings that
  carry no letter at all. On a page of 400 text nodes that is one request of 262 strings where
  it used to be eight requests of 400.
- A string longer than the endpoint accepts is left out instead of being sent. It used to be
  rejected together with the whole batch it travelled in, so up to fifty strings stayed
  untranslated because of one.
