# Changelog 3.2.2

Found by walking every screen of the module on a real TYPO3 13 and checking each fault against
this branch rather than assuming it shared them.

## Fixes
- **Importing a translation file replaced the whole stored file.** `saveAction()` writes the file
  from whatever it is handed, and the import handed it only the units of the uploaded file, so
  sending an export to a translator and importing back the strings they worked on erased every
  other one. The empty-save guard does not catch this: a file with one unit left in it is not
  empty. The imported units are laid over what is stored now, read through `XlfService::parse()`
  so the state of a key the import does not mention survives along with its translation.

  Writing the file is one method shared with the save screen, and the import calls it directly:
  handing a whole file's worth of data to the save action through redirect arguments produces a
  `Location` header the web server refuses with 502.

- The exchange directory an export creates was removed on each return path but not in a
  `finally`, so an exception left it behind, as did the path where the archive turns out empty
  and the plain file is served.

## Changes
- The list of distinct source texts shows how many languages each one has. The query had been
  grouping and counting them all along; only the column was missing.

## Not affected
Three faults of the same sweep stop at the TYPO3 13 line and were deliberately not "fixed" here:
`convertFlexFormContentToArray()` is back on `FlexFormTools` in TYPO3 14 and `FlexFormService` no
longer exists, which is what the entries service already calls, and the row type and import
statistics are already read through their getters.
