# Changelog 3.9.0

## New Features

- **The records of one language can be deleted from the demand screen.** A language on that
  screen is not always demand: a banner that offered a translation where there was nothing to
  translate writes the same rows as a visitor who wanted one, and until those rows age out of
  the retention window they sit on top of every chart and every verdict. The table now carries
  a delete button per language, which opens a screen that counts what would be lost before
  anything is lost - visitor days, months of history, pages, banner rows, banner displays and
  the sources - and deletes them all on a confirmed POST.

  Rows where the language is where a request came *from* are kept: those belong to the
  language that was asked for and say where it was asked from.

  Only administrators see the button or reach the action; the deletion cannot be undone, and
  the language comes back on the screen as soon as somebody asks for it again.

  There is deliberately no "delete only the ones the banner should never have asked for". The
  counting rows never recorded where a request came from - the source is an aggregate of its
  own - so that question cannot be answered from what is stored, and an option that silently
  deleted the wrong half would be worse than none.
